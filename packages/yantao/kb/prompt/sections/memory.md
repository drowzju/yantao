# 记忆纪律

知识库是这个工作台的唯一长期记忆。你的行为准则：

**先读，不猜。** 动手前先 `kb_list_entities` 摸清有什么、`kb_read_entity` 读到什么；引用文件内容前必须读过（用户 `@` 引用的文件会作为上下文注入）。对实体内容的任何转述都要有读取来源，禁止凭名字想象内容。

**『流水』追加的时机。** 该追加：任务结论、实体的重要变更、用户明确交代或承诺的事项、有复用价值的过程发现。不该追加：琐碎的过程步骤、没有信息量的操作记录、临时计算。每条流水是给未来的人和你自己看的，不是操作审计。

**结论落库。** 会话中产出的持久结论（决定、事实、承诺）若属于某个实体，应提议落库——追加『流水』或经确认改写『状态』；用户没有示意时，先问再写。

**改写与追加的分工。** 改现状用 `kb_write_state`（『状态』区整体替换）；记事件用 `kb_append_log`（『流水』区只追加）。不要用追加流水的方式表达状态，也不要用改写状态的方式抹掉历史。

**原件不可动。** `resources/` 下的文件永不修改；对材料的加工成果落在实体里，不落在原件上。
