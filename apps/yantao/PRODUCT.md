# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

单人工具：作者本人（yantao）是唯一用户，在自己的机器上日常运转一个个人知识库——邮件、日程、人物关系、项目、待办、资源文件。没有多用户或对外分发设想。

## Product Purpose

yantao 是**个人认知工作台（Personal Cognitive Workbench）**：实现人机共同进化，最终目的是不断提升个人的认知——知识管理只是手段。人机协作是一个闭环：人在 KB 实体的记录里写下状态与流水，agent 会话消化这些记录并整理成提议（实体更新、记忆、技能改写、邮件整理、调度提议），人对提议做出决策，双方再共同行动，产生的新事实又回到记录里。KB 就是磁盘上一个纯 Markdown 目录（PARA+P 结构），没有数据库、没有私有格式。成功标准：人的认知随这套闭环持续提升，agent 干活，人拍板。

## Positioning

不是又一个笔记软件，而是一套「人机共同进化」的工作机制：数据面是与 Obsidian 互通的纯 Markdown，换工具随时可走；agent 写入 KB 的唯一通道是一小组可审计的 `kb_*` 工具（十四个），UI 是人类通道，每次落库都经一次人类批准动作。「agent 干活 + 可审计工具边界 + 人决信任锚 + 开放数据面」的组合是邻近产品（Obsidian 及其插件、通用笔记工具）拿不走的机制。

## Operating Context

- 桌面 Electron 壳（apps/yantao-desktop）是主战场；同一 UI 也跑在 web 壳（apps/yantao）里。渲染层一律 web 技术（React + TS + cordis 插件），无原生设计语言。
- KB 目录在启动/首跑时与 dsh workspace 对齐（ADR-0013），是所有 kb_* 工具与会话的工作目录。
- 调度任务在后台跑 KB-rooted 会话，其产出解析为提议进入提议队列（ADR-0047）。
- 会话日志、用量账本等运行时产物在用户目录 ~/.dsh 下，不属于 KB。

## Capabilities and Constraints

- 永久中栏 tab：对话、任务、调度、提议、图谱、洞察（外加宿主会话面）；采集栏四区：资源、待办、记忆、能力。
- 能力/技能用于作用于资源和各类 KB 实体（指令型能力、技能改写、惯用提示词）。
- 资源目录的文件格式灵活：不限于 .md（PDF/HTML/eml/图片等原件按字节保存，渲染读取面人人平等，ADR-0046）。
- 硬约束：KB 是纯 Markdown 存储，任何功能不得引入私有格式；与 Obsidian 尽量互通（ADR-0048 四期承诺，二至四期待做）。
- 信任模型：重限制方案不进默认推荐；信任锚放在人类一次性动作上（安装能力、批准提案、批准记忆），运行时不加重限制。
- UI 语言中文优先：zh 字典是 source of truth，en 是编译期对齐的镜像。
- kbd 快捷键展示面已落地（2026-10-09 第四轮评审）：右下角「快捷键」按钮打开只读目录（ShortcutsDialog），键帽实时读注册表 catalog，改键与平台差异自动跟随。

## Brand Commitments

- 名称 yantao；品牌标记是鱼形 mark（YantaoMark，出现在会话英雄区）。
- 中文第一的界面文案；术语固定：KB、实体（领域/人物/项目）、资源、能力、技能、提议、惯用提示词、采集栏。

## Product Principles

1. **数据面开放**：一切知识都是人可读的纯 Markdown 文件；工具可替换，数据不锁定。
2. **agent 干活，人裁决**：每一步落库都收敛到一次明确的人类动作；自动化不越过裁决线。
3. **最少限制**：信任锚前置（安装/批准时刻），不在运行时叠加重限制。
4. **中文第一**：文案、术语、评审都以中文语境为准。
5. **单人规模**：为一个人的几百会话、几千文件优化，不为假想的规模化买单。
