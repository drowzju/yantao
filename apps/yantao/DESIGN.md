# yantao UI 设计规则

> **本文件是 UI 设计规范的唯一正典。** frontmatter 是其中机器可读的部分（`--yt-*` token 家族的浅色主题正典值），供 impeccable 工具链（critique / live panel）消费；暗色值由 `theme-presenter.ts` 按主题写入，组件代码不感知主题切换。修改设计只改本文件，规则正文与 frontmatter 一并维护。（2026-10-10 起 `docs/yantao/design.md` 已并入此处删除。）

本文档定义 yantao 工作台 UI(`packages/client/ui-yantao/**`、`apps/yantao/**`)的设计约定:色彩、排版、间距、表面、构图与反模式。**新代码必须遵守;存量的迁移见第 9 节。** 所有颜色在组件代码里只能以 `var(--yt-*)` 引用,禁止裸十六进制。

约定的设计纪律借鉴自 Vercel 品牌报告规范(单色克制、排版先于表面、证据优先),**只借原则,不引入其资产**(不引 Geist、不引 `vercel-brand.css`)。审美身份是我们自己的:暖纸调的个人工作台。

## 1. 审美立场

yantao 是一个**工具**,不是报告、不是营销页。界面气质:暖纸、安静、克制、信息密度服务于阅读与操作。

- **颜色只在承载语义时使用。** 强调色只有一个蓝;其余颜色仅表达成功/警告/错误/脏状态。不因为某行"重要"或"有利"就上色。
- **排版先于表面。** 用字重、字号、间距、对齐建立层级;边框与底色是最后手段。
- **静为默认。** 动效只用于解释状态变化、保持连续性、确认操作;不做装饰性动效,不用动效门控阅读。
- **留白要有构图目的。** 大块空白必须是在放大焦点;因欠填充、孤立项造成的空矩形是布局失败,重排而不是放着。

## 2. 色彩与语义 token

一切颜色通过 `--yt-*` CSS 变量引用,**禁止在组件里写裸十六进制**。token 值由 `theme-presenter.ts` 按主题写入(浅色/暗色两组),组件代码不感知主题切换。

### 2.1 表面(surface)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-surface-primary` | `#fbfaf7` | `#1b1916` | 页面主底(暖纸) |
| `--yt-surface-secondary` | `#f1f0ec` | `#242220` | 次要分组底、轨道底 |
| `--yt-surface-raised` | `#fffdf7` | `#211f1c` | 浮起层:卡片、对话框、下拉 |

层级靠 surface 分层与间距表达,**不用阴影堆叠**。

### 2.2 文字(text)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-text-primary` | `#2e2b26` | `#e8e4dc` | 正文与标题 |
| `--yt-text-secondary` | `#6b6455` | `#a8a296` | 次要说明、辅助信息 |
| `--yt-text-muted` | `#726c5e` | `#918b80` | 占位、时间戳等从属证据 |

不用比 muted 更浅的文字凑密度;字号与对比度不可为密度牺牲。

### 2.3 边框(border)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-border-subtle` | `#e6e2d8` | `#35322d` | 默认分隔 |
| `--yt-border-strong` | `#d8d2c4` | `#454138` | 需要强调的分组边界 |

### 2.4 强调(accent)——唯一的彩色

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-accent` | `#4a7fd4` | `#7ba3e0` | 链接、选中、主操作 |
| `--yt-accent-text` | `#3a66b5` | `#7ba3e0` | accent 作文字的场合(芯片、链接) |
| `--yt-accent-strong` | `#3a66b5` | `#7ba3e0` | 实心 accent 面——主行动钮的唯一底色 |
| `--yt-on-accent` | `#ffffff` | `#1b1916` | 实心 accent 面上的文字/徽标(暗色的 strong 是亮 accent,白字只有 2.6:1,文字翻墨色) |
| `--yt-accent-bg` | `#eef3ff` | `#232c3d` | 选中态底(不作主按钮) |
| `--yt-accent-border` | `#c7d7ff` | `#3a4d75` | 选中态边 |

### 2.5 语义色(semantic)——只表达状态

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-success` | `#4f9d5d` | `#6fb87d` | 已保存、已完成 |
| `--yt-success-text` | `#38754a` | `#6fb87d` | 成功底色上的文字 |
| `--yt-success-bg` | `#eaf4ec` | `#2a3328` | 成功态底 |

## 3. 排版阶梯

字号只有五档,新代码**禁止取阶梯外的值**:

| token | 大小 | 用途 |
|---|---|---|
| `--yt-type-label` | 12px | 徽标、计数、辅助标注 |
| `--yt-type-body` | 13px | 正文、列表、表格、输入 |
| `--yt-type-read` | 14px | 阅读型表面（§6）的论证正文：proposal 卡、实体阅读视图 |
| `--yt-type-section` | 14px | 面板内小节标题 |
| `--yt-type-title` | 16px | 窗格标题、对话框标题 |
| `--yt-type-display` | 20px | 页面级唯一主标题(一处界面至多一个) |

字体栈只有两条,新代码**禁止内联硬编码**(2026-10-05 第三轮评审 #7:此前
`system-ui` 栈散在七个文件的本地常量里,一处改动要追七处):

| token | 栈 | 用途 |
|---|---|---|
| `--yt-font-ui` | `system-ui, "Microsoft YaHei", sans-serif` | 全部界面文字 |
| `--yt-font-code` | `var(--ds-font-family-code, ui-monospace, Consolas, monospace)` | 路径、ID、时间戳、代码片段 |

- **阅读面单占一档。** `--yt-type-read` 与 `--yt-type-section` 同为 14px,用途不同:section 是面板内小节标题,read 只给 §6 的阅读型表面正文(2026-10-24 评审 P2——中文字形在 13px 下可读但不耐久读,而 chrome 的密度不该被一起放大)。阅读面里的从属证据(为什么、补充说明)退一档到 body 13,标签仍用 label 12,三级关系不变。
- 字重只用 regular / medium / semibold 三档;同级同类元素永远同字号同字重,不因内容长短或数值大小改变。
- 等宽字体(上游 `--ds-font-family-code`)只用于路径、ID、时间戳、代码片段——只设那个标识符本身,不设整句整表。
- 标题用句首大写(中文即自然语句),陈述具体事物;禁止 eyebrow/overline 式的装饰小标、装饰性序号、全大写。
- 段落之间用间距分隔,不用首行缩进;正文行高保持舒适,改写文案而不是缩字号。

## 4. 间距纪律

间距只有六档,新代码**禁止取阶梯外的值**:

| token | 值 | 关系语义 |
|---|---|---|
| `--yt-space-1` | 4px | 最紧:图标与文字、行内元素 |
| `--yt-space-2` | 8px | 组内:标题与其第一段、label 与值 |
| `--yt-space-3` | 12px | 组内:段落与段落、同级列表项 |
| `--yt-space-4` | 16px | 组间:内容组与内容组 |
| `--yt-space-5` | 24px | 大组间:面板内主要分区 |
| `--yt-space-6` | 32px | 章节级:页面上两个实质部分的转场 |

- **每个 gap 只有一个 owner**:由父容器的 gap/stack 设定,子元素不得再加竞争性 margin 参与同一段间距。修一个别扭的间距时,修分组或 owner,不打一次性的 arbitrary margin 补丁。
- 间距表达的是**关系**:关系近则小,关系远则大;不是全界面一把统一 stack。
- 判断整个过渡而不只看 token:大间距挨着欠填充的分区会放大空洞感,该收间距、重排或堆叠。

## 5. 表面与边界

- 页面默认是**一张连续画布**;表面或边界只在表达选择、交互、警告、状态或真实分组时"赚用",分组能用间距表达就不用边框。
- **三栏页签一套构造。** 左采集栏、中栏、右工作区栏的 tab 头共用同一副脸(buttons.ts 的 tabItem 面):border-box 28px 命中高、`--yt-type-body` 字阶、透明底圆角 4;激活态一律 accent 洗染(`--yt-accent-bg` + `--yt-accent-border`),只换底与边、不动字色。「当前在哪」全工作台只有一种说法(2026-10-12 评审裁决:此前中栏凸面页签与两栏 accent 洗染并存,同屏两套选中语法)。三栏页签**同高同顶**:栏的顶内边距与中栏页签条一致(space-1),激活页签必须带 `data-selected`,否则悬停被通用规则涂灰,激活色"一会蓝一会黑"(2026-10-12 截图评审补裁)。
- **页脚是重开入口，不是第二套导航。** 底部那排开关与中栏页签指向同一批目的地，这不是「两种说法」：页签说「现在在哪」，页脚说「怎么回去」——关掉的固定页签只能从这里重开，徽标也只能挂在这里（它的页签已经不在了）。两处选中态同一套 accent 洗染（2026-10-23 P1-4），同屏永远同亮。2026-10-24 评审曾提议把两排收成一套，裁决保留现状：收成一套要把「重开」塞回页签条，代价大于收益。
- **列表行一律单行省略。** 文件名、实体名等列表行不折行——三折行的长文件名让整棵树无法扫读;溢出 ellipsis,全名由行的 `title` 兜底(2026-10-12 截图评审)。目录行有 ▸/▾ 的地方,文件行配弱墨 `•` 叶子标记,节点类型不靠缩进猜。
- 禁止:卡片套卡片、渐变、发光、玻璃拟态、装饰性阴影、纹理、网格背景、彩色侧栏。
- **圆角只有六档**,新代码禁止取档外值(2026-10-14 立档——此前 2/3/4/6/8/10 六种取值散在各组件,本文档无正典):

| 半径 | 用途 |
|---|---|
| 2 | 迷你状态点(≤8px 的小圆点) |
| 3 | 小标记:状态点、微型进度/标记条 |
| 4 | 控件与列表行:页签、行容器、行内 tool 钮、输入框 |
| 6 | 按钮(主/幽灵/浮起) |
| 8 | 卡片行与徽标胶囊 |
| 10 | 模态卡与对话框 |
- **分类不上色。** 图谱一类"给事物分门别类"的表面,类别靠形状与标签区分(圆 / 圆角方块 / 菱形),节点与连线一律中性墨色,线型(实线 / 虚线 / 点线)承担关系种类;唯一的蓝留给"当前聚焦"。拿成功绿、警告黄当分类色,等于把"好/坏"的语义偷渡进中性的分类里(2026-10-23 评审)。
- 感觉"闹"时,减少颜色、字重、边框、表面之间的竞争,**保留一个刻意的锚点**——克制不等于把页面抹成中性均质。感觉"挤"时,删、并、重排内容,而不是缩字号、压间距。
- 不用面板、边框、图标、色块去填证据缺口;内容薄就改善选择与层级,缺口就诚实地空着。

## 6. 阅读型表面构图

proposal 卡片、提炼裁决、邮件分诊结果、实体文档阅读视图等**给人读的论证表面**,额外遵守:

- **双层阅读**:executive 路径(标题、结论、关键值)让忙的读者快速抓住论点;audit 路径(完整记录、来源、限定条件)保留可查证的档案,但不主导第一读。
- **一个焦点关系**:每个阅读时刻有一个主导对象,其余退为支持;同级元素才允许重复成排,非同级重复是模板噪声。
- **标题即论点**:小节标题陈述具体发现或读者问题,不命名文档体裁("概述""详情""其他"是失败标题)。
- **表格是证据**:数字列连同表头右对齐、文字列左对齐;同级单位与精度一致,不伪造精度;表格默认占满所在分区的证据宽度;五个及以上列的表不做窄分栏。
- **结尾落在决定**:页面或卡片收在已解决的决定、含义、下一步或未决问题上;不在一段台账或免责后戛然而止。
- **活动日志的贴底跟随**:只读日志面(`.log`)开启刷新跟随时,仅当读者本就停在底部才随新内容下移,离开底部即冻结视口——跟随服务阅读,由读者的位置决定是否挪动(区别于第 8 节所禁的装饰性自动滚动)。
- 图标只在显著加快识别时使用;不做装饰图标、图标彩色底砖。不用 stock 图、假截图。

## 7. 操作型表面:管理列表与表单行

记忆、待办、配置等**给人操作的管理列表**(区别于第 6 节的阅读型表面),额外遵守:

- **低频创作入口默认收起。** 管理列表的新增动作收成一个按钮,点击才展开编辑区——编辑区独占一张浮起卡片、控件纵向堆叠,输入得以占满栏宽;保存/取消后收起。常驻表单行只在高频创作时才值回它挤占的那一行;被迫给常驻行的 select 打"紧凑定宽"补丁,通常就是该收起的信号。
- **表单行里主输入是主角。** 输入框吃 `flex: 1` 剩余空间;同行的辅助控件(select、按钮)必须显式限宽——原生 select 的宽度由最长选项决定,不限宽会把主输入挤到只剩几个字的可视宽度。限宽要按**常见选项**给紧凑定宽,而不是按最长选项给上限(否则上限永不触发);长选项在收起态截断、在下拉展开态完整,全名由 `title` 兜底。
- **行内动作顶对齐。** 多行文本块配 `align-items: baseline` 会把动作按钮的视觉重心沉到文本块中部;管理列表的行内动作用 `flex-start` 钉在首行,或收进 meta 行。
- **从属证据独立成行。** 时间戳、来源等从属信息用 muted + `--yt-type-label` 自成一行,不用 ` · ` 直接缀在正文末尾——正文一折行,尾巴就漂进段落里认不出归属。**豁免(2026-10-14 复评追问的裁决):运行摘要/计数类的统计行不受此限**——「手动 · 成功 · 09:30」这类同级事实的并列枚举整行都是元数据,不存在"缀在正文后"的主体,拆行反而碎;禁的是把从属尾巴挂在正文句末。
- **同级条目用间距分界。** 条目间隔取 `--yt-space-3`,每段间距只有一个 owner(如每行各自的 marginTop 阶梯);分组能用间距表达就不用边框(第 5 节)。
- **低频破坏性动作穿 ghost 装。** 每行一个的删除类按钮无边框、透明底、muted 墨色,不挂实体按钮皮;动作说明放 tooltip。
- **落盘前给出改动摘要。** 设置类对话框(模型配置、工作空间 CLI、钉钉)的表单改动未落盘时,页脚上方给一行摘要:「将改 N 处:字段 · 字段」,走 `--yt-warning-bg` 底与 `--yt-warning-text` 墨(第 2.5 节的未保存提示条语义);无改动时不渲染,不拿「无改动」占一行。只列**落盘才生效**的字段——即时提交的开关(钉钉「并入工作台会话」)不属于草稿,不进摘要。密钥栏留空表示「保持已存」,不算改动;填了新值按「替换已存」措辞报出。

- [ ] 卡片/边框用来修补层级,而不是表达真实分组
- [ ] 给"重要"或"利好"的内容上色
- [ ] eyebrow/overline、装饰性序号、全大写小标

## 9. 迁移路径

现状:ui-yantao 全是内联样式 + 硬编码暖纸 hex,light-only,暗色下我们的 pane 不换肤。本文档只定约定,**迁移是独立任务**,不捆绑进行。迁移分三步:

1. **token 落地**:`theme-presenter.ts` 在现有主题写入机制上增发本文档第 2–4 节的 `--yt-*` 一族(浅/暗两组值)。
2. **逐 pane 迁移**:按窗格把内联样式改为引用 token;一次一个 pane,顺带清理阶梯外取值,不做顺手重构。
3. **上门禁**:迁移完成后,给 ui-yantao 加检查(禁裸 hex、禁阶梯外 px),作为迁移的收尾动作。在此之前执行靠 code review 自觉——存量全是违规时上门禁等于立刻红一片。

暗色 token 值在第 1 步落地时以实际渲染效果微调,本文档表格中的暗色值为基准。

## 10. 裁决动作的危险分级(2026-10-14 裁决)

裁决面按钮的闸门跟着**动作的后果**走,不跟着按钮的形状走:

| 动作 | 闸门 | 理由 |
|---|---|---|
| 批准(确认写入 N) | 至少勾选一项才可点 | 往知识库写真数据;勾选投入本身就是闸门 |
| 丢弃(提议) | 无——单击即决 | 什么都不写;条目留痕带「已丢弃」芯片,台账有审计行,误丢弃用「重新入队」原样投回 |
| Esc(裁决卡) | 勾选过行才武装(4 秒窗口) | 保护的是人刚投入的勾选劳动,不是提议本身;空手 Esc 保持一等逃生口 |
| 真删除(记忆/调度/待办/能力) | 两击武装(useArmedAction) | 销毁的是已入库、不可再生的数据 |

- 2026-10-12 评审 P1-1 曾给收件箱行级丢弃套上两击武装——那是按「行尾危险钮」的形状归并,不是按丢弃的后果定的级;本裁决将其退役,武装回归真删除专用。
- 「重新入队」不是撤销决策(决策终态不可改,入库闸门单向),而是内容原样产生一条新的待决提议;旧的已丢弃条目留在列表当痕迹。
- 「重新入队」有两扇门,并存是刻意(2026-10-14 复评追问的裁决):行尾直投是熟练者的快速通道,卡底的「看完再投」给想先复查内容的人——已裁决条目可点开只读卡后,两扇门各自服务一种确定的心智,不强迫任何人多走一步。
