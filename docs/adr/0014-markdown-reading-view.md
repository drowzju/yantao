# 打开 markdown 是阅读视图（v1）

决定：

1. **打开 `.md` 默认是渲染出来的阅读视图**，不是 textarea。tab 条上给「阅读 / 源码」两个按钮，切到源码是原来的
   `FileEditor`（自动保存 + 保存前比对 + 冲突条，一行没改）。
2. **渲染复用 `MarkdownText`**（`@deepseek-ai/dsh-client-ui-primitives`）。它已经是 shell 的静态种子模块，
   且和 agent 回答用的是同一套渲染——阅读视图里看到的样子和中栏对话里的样子一致。零新增体积。
3. **两个视图共用一个加载器**：`FileEditor` 仍然持有草稿与基线（它是唯一会写的地方），只多了一个 `onDraft` 回调把
   草稿上报给框架；阅读视图显示这份草稿。不二次读文件，也就不会出现两套基线。
4. **源码编辑器在隐藏时保持挂载**（`display: none`，沿用中栏"隐藏而非卸载"的既有做法），切换视图不丢草稿。
5. **YAML frontmatter 折起来**：文件开头的 `---` 信封由前端纯函数 `splitFrontmatter()` 剥掉，折叠成一行摘要
   （`type: project · relation: peer`），点「属性」展开成一张字段表格。正文区不再出现信封。
6. **范围**：所有 `.md`（含 `entities/todos.md` 与 `resources/` 下的 `.md` 影子笔记）。非 md 的 resources 原件
   仍是 `<pre>` 原文只读，不提供切换（没有可渲染的东西）。
7. **待办内联 checklist 不动**：它是控制台不是文档视图；只对「打开全文」出来的那个 tab 用阅读视图。
8. **不做所见即所得编辑**，改为给「在 Obsidian 中打开」留位置（`obsidian://` 深链，v1 未接线）：KB 文件本来就是
   给人用 Obsidian 打开的，为了在网页里编辑而重写一套富文本编辑器，会同时踩到格式和 agent 同写两个坑。
9. **Mermaid、本地图片、双链、反向链接都不在 v1**（见下）。

原因：

- **为什么推翻 ADR-0012 的"不做渲染切换"**：那条决定保护的是"写"——不让 UI 把文件格式钉死。它顺带把"读"也牺牲了：
  打开一个实体先看到三行 YAML 加一堆 `##`，而人打开 KB 的绝大多数动作是读。现在只放开"读"，"写"继续走原文，
  保护的东西没丢。**只推翻这一条**，ADR-0012 的其余部分仍然有效。
- **为什么不做所见即所得**：文件里有 `## 状态` / `## 流水` 锚点（工具按锚点拼接文本）和 `---` 信封，而 agent 也在写
  同一批文件。富文本编辑器接管写入意味着格式由编辑器决定，`kb_write_state` 迟早和它互相踩。
- **为什么信封由前端剥而不是后端返回结构化**：`MarkdownText` 没有注册 frontmatter 扩展，`---` 会被解析成
  "分割线 + 段落 + 分割线"渲染成垃圾，所以必须剥；但这是"怎么显示"的问题，不值得为此改 `KbFileContent` 契约
  （改契约意味着客户端 face 整体重编，也是上次 `intakeTree is not a function` 那类坑的入口）。
- **为什么解析器只认 `key: value`**：信封是 `packages/yantao/kb/src/templates.ts` 机器写出来的，没有锚点、块、引号。
  宁可解析不出来退回原文（同"没有信封"处理），也不要一个半吊子 YAML 解析器把文件读坏。
- **为什么复用 `MarkdownText` 而不是自研**：自研要重造表格、代码高亮（shiki）、公式（katex）和脚注，
  而且会失去"和 agent 回答同一套观感"这个好处。它的缺口（不认信封、任务框 disabled、无 Mermaid）都能在它外面补。

后果：

- `ui-yantao` 新增 `@deepseek-ai/dsh-client-ui-primitives` 依赖（只进编译期，运行期是 shell 种子模块，不打进包）。
- `FileEditor` 多了一个可选 `onDraft`；它自己没有行为变化，11 个既有测试不动。
- 阅读视图没有写路径：勾选任务框、点链接都还不行——**v2 才做任务框可勾选**（`MarkdownText` 渲染的 checkbox 是
  disabled，需要事件委托按"第 N 个 checkbox"映射回源码行，再走 `FileEditor` 已有的保存前比对）。
- 已知不做：Mermaid（客户端包是单文件 CJS，mermaid 会被内联成 ~3.5MB 且懒加载 chunk 活不下来）、
  本地图片（`read()` 是 utf8，二进制会被解坏，要新 RPC + 宿主路由）、`[[双链]]` 与反向链接（KB 内尚无链接语法，
  需先定语法并新增 `links(path)` RPC）。这四项按 v2→v4 分期，各开各的 ADR。
- 未接线：阅读视图里的链接点击目前走浏览器默认行为（外链正常，`[[…]]` 还只是纯文本）。
