# 实体校验（validate 手势）

ADR-0029/0030 建起了「资源 → 实体」方向的闭环（归入、提炼、提炼到实体），但知识库缺第三个基本操作：**体检**。Karpathy 的 LLM-wiki 方法论把三大操作定为 Ingest / Query / Lint——我们前两个都有了，第三个没有。今天的库靠自己生长：孤儿条目（入链寥寥、与全网脱节）没人看见；失效双链（`[[…]]` 解析不到目标）静静躺在正文里；「这里其实该有个实体/该有条链」的判断完全依赖人在阅读时灵光一现。本 ADR 补上这一环：**实体校验 (validate)**——一个手动手势，对全库做确定性预扫 + 模型研判，产出一张开箱即用的提议卡。

事实基础（已核实）：提议卡是纯客户端产物——refine/邮件分析都是客户端开专用命名会话 → `jsonRound` 拿 JSON 裁决 → `verdictToProposal` → 弹卡（`refine.ts`/`mail-analysis.ts` 同构）；普通聊天会话里 agent 的 `kb_*` 写入**直接生效**不经人批（ADR-0026），所以「体检结论要人批」排除了指令型能力路线。`yantaoKb.links(path)` 是单路径查询，Frame 只按活动路径调；`KbLinkTarget` 解析不到目标即为 `null`——失链检测在数据层是白送的，但**全库链接图今天没有任何一处持有**。verdict v2（ADR-0030）是「一份资源 → 相关实体」的形状，体检没有单一资源主体，顶层形状不能直接套用，但 `targets[]/creates[]` 的条目形状与整套解析/转换/落盘机制可以原样复用。无调度机制：ADR-0029 已把自动定时提炼列为未做，上游 `jobs` 包是会话内长任务契约而非 cron。提议卡动作十一种，行级勾选、部分批准、apply 重读重定位均已就绪（ADR-0030/0031/0033）。

决定：

1. **第四个手势：实体校验 (validate)**。~~工具栏按钮（「提炼」旁），点击弹小对话框选等级~~（**2026-09-29 修订**：入口改为**人物 / 项目两个 tab 内、「新建」旁的「校验」按钮**，各自以该类实体为视角触发——预扫清单只收该类实体的孤儿与失链，花名册保持全库（补链可指向任何实体），会话命名相应区分为「实体校验·人物 <日期>」/「实体校验·项目 <日期>」；等级对话框随之取消，L1 直接启动，L2 待 ADR-0036 施工时再回到入口设计）。校验是**全量扫描**：预扫全库，模型研判覆盖全部实体。
2. **确定性预扫先行**。controller 新增 RPC `yantaoKb.graph()`，一次返回全库双链图（全部实体的 outgoing/incoming）。客户端据此现算两份确定性问题清单：**孤儿条目**（入链 ≤ 1）与**失效双链**（target 为 `null` 的链接及其宿主）。清单有三重用途：直接构成 L1 的确定性问题行；作为模型研判的输入线索；让模型的注意力花在判断上而不是大海捞针上。这是 `yantaoKb` 的第二十二个 RPC——controller README、ADR 索引、TODO、`gen-cordis-catalog` 四处台账随落地同步。
3. **校验裁决协议**：`ValidateVerdict = { findings[], targets[], creates[], todos[], questions[] }`。`targets[]/creates[]` **逐字段复用** ADR-0030 v2 条目形状（`edits[]/links[]/log`、`afterCreate` 追随机制），解析与 `verdictToProposal` 走同一套代码；`findings[]` 是新物种——`{ kind, subject, why }`，kind ∈ `orphan`/`broken-link`/`stale`/`contradiction`/`missing`，在卡上呈「发现」分组：**纯展示行，不可勾选、不产生动作**，供人了解与追溯（对应的修复动作如果模型提出了，会在各自的动作分组里）。`questions[]` 复用 ADR-0030 第 5 条的两段式语义（至多一轮）。空行一律丢弃的立场照搬。
4. **动作白名单与分级**。L1 只允许**建页与建链**：`creates[]`（新建实体，创建性 edits 属于新文件自身内容，放行）与 targets/creates 里的 `links[]`；targets 条目的 `edits[]` 提示词钉死为空。L2 解锁两项：targets 的 `edits[]`（`edit-section` 修措辞——过期断言的修复走这里）与 `todos[]`（映射 `add-todo` 动作行）。**`write-state` 永远不在白名单里**——整区改写太粗暴，改措辞 `edit-section` 足够。L1 的模型输入：花名册整体注入（复用 8k 截断防线）+ 预扫清单点名实体的全文（逐个 8k 截断）。
5. **L2 = L1 的超集，分批接力，施工另立 ADR-0036**。L2 在 L1 之上增加陈旧迹象与内容矛盾的通读研判：**按实体类型分批**（五类各一个独立会话，串行执行），每批独立 `jsonRound` 出部分 findings/actions，最后客户端**合并成一张卡**；卡头标注覆盖批次。某批失败即停、**不自动重试**，已完成批次照常合并成部分卡并注明缺失批次；统计照常汇总（含失败批次开销）。L2 通读沿用 8k 截断防线。本 ADR 只定格 L2 的这些决策，施工（会话串联、跨批合并、批次进度）走 ADR-0036 单独一小步——L1 上线后的真实反馈会直接影响批次粒度与合并策略。
6. **进度与统计**。阶段级进度（预扫 → 模型研判中 → 出卡）走既有手势反馈区/任务 tab（ADR-0031），不做逐条目进度条。完成时给一行汇总：**实体数、发现数、token 用量、墙钟时间**；L2 另附每批明细（批名/token/耗时，折叠可看，usage 由 session 事件求和）。历史统计不持久化——批准过的卡本来就在流水里留痕。
7. **产出只弹卡，不落盘报告**。报告的价值已被卡片行承载（每行 = 发现 + 建议动作），落盘会引来「报告放哪、算不算 KB 内容、谁清理」一串新问题。
8. **不注册指令型能力，不留聊天口令**。产出通道唯一（提议卡）。将来若要在对话中唤起，应由客户端拦截口令转成手势、走同一条编排路径，而不是让 agent 在聊天会话里自行体检、直接改文件。

## 取舍台账——为控制牺牲的便利性

| # | 牺牲 | 换来 | 重开条件 |
|---|---|---|---|
| 1 | 只弹卡不落盘报告 | 零新文件生命周期问题；处置清单即卡片本身 | 需要跨次体检比对趋势时设计报告投影 |
| 2 | L1 不做全库正文通读（花名册 + 点名实体，8k 截断） | token 可控、行为可预测 | L1 漏检率真实伤人时扩样本 |
| 3 | L2 通读沿用 8k/实体截断 | 分批后每会话预算可控 | 截断伤矛盾判断时把批切得更细 |
| 4 | 批次失败不自动重试，部分交付 | 重跑是真金白银的 token，能保住的批次就保住 | 环境性失败占比高时加一次有界重试 |
| 5 | ~~等级不持久化，每次显式选~~（2026-09-29 修订：等级对话框随入口修订一并取消，此条暂不存在；L2 落地时重估） | 高档烧钱，误触代价不对称 | 使用频率证明默认档烦人时记住上次选择 |
| 6 | 无调度、无口令，手势是唯一入口 | 产出通道唯一，人批语义不被第二条路稀释 | 口令拦截转手势的需求成真时立补充 ADR |
| 7 | findings 纯展示、不可单独执行 | 卡的勾选只落在动作上，「发现」与「处置」不混淆 | 「只要报告不要动作」的使用姿势出现时再议 |
| 8 | `write-state` 永不在白名单 | 状态区整区改写的爆炸半径不进体检 | 无——这是立场不是缺陷 |

原因：

- **为什么客户端编排而不是指令型能力**：体检的存在意义是把「该修什么」交给人裁决。指令型能力让 agent 拿着 `kb_edit_section` 直接改（ADR-0026 允许），人批退化成事后追认——与初衷相悖。客户端编排完全仿 refine 骨架，专用会话 + 结构化裁决 + 提议卡，人批是硬保证。
- **为什么预扫先行**：孤儿与失链是纯图计算，零 token、零幻觉，还恰好是模型研判最好的路标——「这几个孤儿之间该不该有链」「这个失链是想改成什么」。让模型把预算花在判断上。
- **为什么新 verdict 而不是硬塞 RefineVerdict**：主体不同（体检没有「这份资源」），`findings` 是新物种；但 targets/creates 条目形状、解析、`verdictToProposal`、applier、串行队列全部原样复用——新的是顶层形状，不是机制。
- **为什么 `graph()` RPC 而不是 N+1 次 `links()`**：一次往返换来全图，语义干净；且「相关条目」面板（来源重叠 + 直接链接的简化关联度）是它的天然第二消费者，一举两得。
- **为什么 L2 另立 ADR**：多会话接力（串联、部分失败、跨批合并）是独立的编排工程；ADR-0035 把决策定格，施工粒度等 L1 的卡片体验与统计口径经过实战再说。

后果：

- `packages/api/yantao-kb-controller`：新增 RPC `yantaoKb.graph()`（`types.ts` 增结果类型、`index.ts` 增实现，复用 `packages/yantao/kb` 既有的链接解析）；controller README 计数同步；`gen-cordis-catalog` 重跑。`kb_*` 工具保持十一。
- `packages/client/ui-yantao`：新增 `validate.ts`（预扫计算、L1 提示词、`ValidateVerdict` 解析、复用 verdictToProposal）；`Frame.tsx` 增手势、等级对话框、阶段进度与完成汇总；locales 增词条；client bundle 重建。
- 文档同步：`docs/yantao/README.md` ADR 索引（本条）、`docs/yantao/TODO.md` next 行、`packages/yantao/CONTEXT.md` 增「实体校验 (Validate)」词条（随落地）。
