# 待办的载体：`[due::]` 结构化行 + 左栏 TODO/DONE 双面板

决定：

1. **待办仍然是单例**（`entities/todos.md`），ADR-0010 那条不动；变的是行：

   ```
   - [ ] [due::2026-09-12] 把季度汇报发给张三
     正文是自由 markdown，缩进恰好两格
   - [x] [due::2026-09-10] [done::2026-09-09] 已经做完的事
   ```

   `[due::]` 是截止日期，`[done::]` 是完成日期，字段顺序固定 due → done，都可选。
   标题是字段之后的全部文本。正文是紧随其后、缩进两格的行，空行结束该条。
   条目之前的内容（比如一个 `# 待办` 标题）作为 preamble 原样保留；
   不认识的 `[key::value]` 也原样保留。
2. **语法用 Dataview 的 `[key::value]`**，不用自造的 `due:2026-09-12`，也不用 Tasks 插件的 `📅`。
3. **左栏「待办」tab 内分上下两块**：上 TODO、下 DONE。TODO 按 `due` 升序排，
   没有 deadline 的沉到最后，已过期的标红；DONE 灰显。
4. **编辑在左栏内联展开**：标题输入框 + 日期 + 正文 textarea，就地写回文件；
   面板底部「+」新增；每条可删。
5. **解析与序列化只有一份实现，在宿主侧**（`packages/yantao/kb/src/todo.ts`），
   界面通过新增的 `yantaoKb` RPC 读写结构化待办。
6. **不给 agent 新增写待办的工具**：`kb_*` 仍然是七个。邮件分析产出的待办，
   在人点确认之后由界面写进 `todos.md`。
7. 待办文件**不带** `状态` / `流水` 区段，因此 `kb_*` 工具依然碰不到它——这是有意的，不是缺陷。

原因：

- **为什么保持单例而不是每条一个文件**：待办的价值在于"扫一眼今天要做什么"，
  拆成 N 个文件后这个动作就没了，换来的是一堆空架子文件。而 deadline 和正文用行内字段
  就能装下，不值得为它们推翻 ADR-0010。
- **为什么是 Dataview 语法**：知识库本来就在 Obsidian 里当 vault 打开（ADR-0017），
  `[due::]` 让"查本月到期的任务"变成一个 Dataview 查询，不用我们做任何事。
  `📅` 是 Tasks 插件的私有方言且非 ASCII；自造的 `due:` 在 Obsidian 里毫无意义。
- **为什么排序和过期标红**：有 deadline 却不按它排序，等于没有 deadline。
- **为什么唯一实现放在宿主侧**：不是偏好，是约束。客户端**不能** import 宿主包的值——
  `packages/client/tsdown.client.ts:489-499` 有一道 purity 闸门，白名单 `INLINE_SAFE`（:61）里
  没有 `dsh-yantao-kb`，硬 import 会让 bundle 构建直接抛错。剩下的三条路里，
  复制两份迟早漂移；为一个 40 行的解析器开一个新包，要付双语 README 三件套 + 配对重录 +
  `gen-tsconfig-paths` + 若干 verify 脚本 + 手工加白名单，不值。
- **为什么不给 agent 开写待办的工具**：ADR-0004 的边界是"工具集"，每加一个工具就扩大一次
  可写面。而"邮件 → 待办"这条链路中间本来就有一次人工确认，让界面来写是零成本的。
  哪天真觉得在对话里喊"加个待办"别扭了，再开。

后果：

- 旧的纯 checkbox 行（没有字段）必须照常读得出来：解析器对无字段行正常工作，
  `due` 缺省即可。**不需要迁移脚本。**
- `yantaoKb` Remote 多两个方法 `todos` / `writeTodos`。**改 Remote 契约必须跑
  `pnpm run build:lib`（host → client 顺序）**，否则浏览器拿到旧方法表——
  这正是 ADR-0015 曾经"在服务端存在、在浏览器不存在"的原因。
- 写走**乐观并发**：界面提交 `expectedText`，宿主拿它跟磁盘上的当前文本比对，
  不一致就拒绝。这跟编辑器 autosave 的 pre-save 比较（ADR-0012）是同一个语义，
  不引入第二种并发模型。
- 待办不进 `kb_*` 工具的可写范围，所以"agent 自己整理待办"这条路仍然是关的。
- 未做：待办与实体的关联（比如"这个待办属于哪个 project"）、重复/周期待办、
  DONE 的自动清理。DONE 面板本身就是归档视图，删条目是人的动作。
