# 一级导航收敛：六页签并三页签

出发点（2026-10-11 界面内聚性讨论）：中列一级页签已涨到六个（对话/任务/调度/提议/图谱/洞察），
左下 footer 还有一对切页签的快捷按钮（调度、洞察）。问题不是功能多余，而是层级平坦——
「任务/提议/调度」同属「事情的管理」一面，「图谱/洞察」同属「库的观察面」，却各自占一个一级入口，
视线在六个平级页签间跳。裁决：一级页签收敛为三个（对话/任务/洞察），相关功能下沉为页内分区；
footer 的两个切页签按钮随之退役。

事实基础（已核实）：

- 六个永久页签的 pane 全部无条件渲染、非激活仅 `display:none`（CenterPane）——对话草稿、
  滚动位置、文件编辑草稿都靠这套 render-once 机制活着，任何合并不得改成条件卸载。
- 永久页签不持久化、无 URL/hash（`persistTabs` 只存文件页签路径），合并无兼容包袱。
- 两个既有徽标都在页签条上：任务的运行中计数（本地 taskRows）、提议的 pending 计数
  （30s 轮询 `proposalInboxList`）；footer 按钮上没有任何徽标。
- footer 洞察按钮的边框兼任上下文压力指示（amber >80%、红 >95%，`occupancyStroke`），
  数据经 `footer.insights` 槽（session-maybe 作用域）拿到 `useProjection('contextPressure')`——
  按钮删除后这个信号必须搬家，且仍需 session-maybe 作用域才能读到投影。
- 快捷键 Digit1-6 六跳表绑死六个页签（`WORKBENCH_TAB_JUMPS`），合并后 4-6 悬空。
- 图谱是需要整片面积的力导向画布；洞察 pane 本体不滚、上下两区可拖分隔——两者纵向堆叠会互相挤压。

决定：

1. **三个永久页签**：对话、任务、洞察。`SCHEDULES_TAB`/`INBOX_TAB`/`GRAPH_TAB` 三个常量删除。
2. **任务页 = 上（任务｜提议）下（调度）三区**：上半左任务右提议（横向可拖分隔，默认 60/40），
   下半调度（保留其内部「定义列表+编辑器」双栏），上下可拖分隔（默认 55%）。三区各带一枚
   小节Caption（任务/提议/调度）标明身份。ProposalCard 裁决弹层方式不变。
3. **洞察页内分子页**：页签条下方一层小子页签——「关系图谱」｜「上下文信息」，互斥显示，
   默认上下文信息；子选择会话内记忆（组件 state，不持久化）。上下文信息即原洞察 pane
   （会话仪表盘 + 跨会话总览），内部结构原样；懒加载门控收紧为「页签激活 ∧ 子页=上下文信息」。
4. **双徽标并列**：任务页签上同时挂运行中任务数（accent 底）与提议 pending 数（accent-strong 底），
   沿用各自现有配色与 `data-*-badge` 测试钩子——提议 pending 是等人裁决的催办信号，
   下沉进页内会失去可见性。
5. **压力指示迁到洞察页签**：`footer.insights` 槽退役，新设 `center.insights.pressure` 槽
   （同为 session-maybe），内容是一枚小圆点，颜色走同一 `occupancyStroke` 阈值，挂在洞察
   页签文字旁——全局可见、不占新面积。
6. **footer 只做减法**：删调度、洞察两钮，剩配置、快捷键，其余不动。
7. **快捷键三跳**：Digit1-3 跳三个永久页签，Digit4-6 废除不重排——子区跳转要把「跳页签+
   点子区」两步语义塞进一个键，心智负担大于省的操作；测试断言同步改三跳。

取舍台账：

| # | 牺牲 | 换来 | 重开条件 |
|---|---|---|---|
| 1 | 调度编辑器被压进下半屏，编辑高度变小 | 一级入口 -3，事情的管理聚成一页 | 上下分隔拖到上限仍不够用时改抽屉编辑 |
| 2 | 图谱失去独立一级入口，多一次子页点击 | 观察面聚成一页，页签条不再拥挤 | 图谱成为日均高频入口时升回一级 |
| 3 | 任务页签双徽标，页签条信息密度略升 | 两个催办信号都不丢 | 徽标互相干扰阅读时改合成「n+m」单徽标 |
| 4 | Digit4-6 空置，老肌肉记忆失效 | 不引入两步语义的单键 | 有人实际要求子页直跳时再分配 |

原因：

- **为什么合并而不是收纳**：六个一级页签的问题是层级平坦而非数量——相关的功能彼此隔着一个
  页签距离，聚合成页内分区后才谈得上「内聚有层次」；单纯把页签做成两组折叠并不减少切换成本。
- **为什么图谱用子页签而不是堆叠分区**：画布类界面（缩放/拖拽）对面积敏感，洞察 pane 又是
  「本体不滚、双区可拖」的满幅布局，纵向叠放两边都残；子页签互斥显示让两者各自保住整幅。
- **为什么压力指示跟着洞察页签走**：它的语义就是「当前会话的上下文有多满」，洞察页签是这个
  语义的自然归宿；放在会话区头部则与 token 表重复，单独一行又添面积。
- **为什么快捷键不重排到子区**：跳子区意味着按键行为依赖页签当前状态（先跳页签再点子页），
  单键承载两步语义违背「最少动作」直觉；空置比勉强映射干净。

后果：

- `packages/client/ui-yantao`：`tabs.ts` 删三常量；`CenterPane.tsx` 三页签 + 双徽标 + 压力点缀；
  新 `frame/TasksHubPane.tsx`（三区组合布局）；`InsightPane.tsx` 加子页签外壳（图谱区作为
  owner prop 注入）；新 `frame/InsightsPressureMark.tsx` 替代 `InsightsFooterButton.tsx`（删除）；
  `Frame.tsx` footer 减法 + 组合装配；`shortcuts.ts` 三跳表；`locales.ts` 增子页签文案。
- 槽面变化：`footer.insights` 退役，`center.insights.pressure`（session-maybe）上岗；
  `CenterInsightsOwnerProps` 增加 `graph`。
- 测试：`workbench.client.spec.tsx`（`data-tab` 断言改三项）、`shortcuts.client.spec.ts`（跳表改三）。
- 生效条件：纯前端，刷新客户端 bundle 即可，无需重启工作台。

修订（2026-10-11，任务页改子页签）：决定 2 的三区组合布局实装后显得拥挤——上半两栏各被
压到半幅、调度编辑器再砍一刀。裁决改为与洞察页同构的子页签外壳：任务/提议/调度三个子页
互斥显示，默认任务，子选择会话内记忆。与洞察壳的一点差别：三个子页**保持挂载、只切
`display`**——调度编辑草稿和打开中的 ProposalCard 不能因切子页而丢，与中列页签的
render-once 交易同一逻辑。双徽标、压力点缀、快捷键三跳等其余决定不变。
