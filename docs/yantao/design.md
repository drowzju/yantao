# yantao UI 设计规则

本文档定义 yantao 工作台 UI(`packages/client/ui-yantao/**`、`apps/yantao/**`)的设计约定:色彩、排版、间距、表面、构图与反模式。**新代码必须遵守;存量的迁移见第 8 节。**

约定的设计纪律借鉴自 Vercel 品牌报告规范(单色克制、排版先于表面、证据优先),**只借原则,不引入其资产**(不引 Geist、不引 `vercel-brand.css`)。审美身份是我们自己的:暖纸调的个人工作台。

## 1. 审美立场

yantao 是一个**工具**,不是报告、不是营销页。界面气质:暖纸、安静、克制、信息密度服务于阅读与操作。

- **颜色只在承载语义时使用。** 强调色只有一个蓝;其余颜色仅表达成功/警告/错误/脏状态。不因为某行"重要"或"有利"就上色。
- **排版先于表面。** 用字重、字号、间距、对齐建立层级;边框与底色是最后手段。
- **静为默认。** 动效只用于解释状态变化、保持连续性、确认操作;不做装饰性动效,不用动效门控阅读。
- **留白要有构图目的。** 大块空白必须是在放大焦点;因欠填充、孤立项造成的空矩形是布局失败,重排而不是放着。

## 2. 色彩与语义 token

一切颜色通过 `--yt-*` CSS 变量引用,**禁止在组件里写裸十六进制**。token 值由 `theme-presenter.ts` 按主题写入(浅色/暗色两组),组件代码不感知主题切换。

### 2.1 表面(surface)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-surface-primary` | `#fbfaf7` | `#1b1916` | 页面主底(暖纸) |
| `--yt-surface-secondary` | `#f1f0ec` | `#242220` | 次要分组底、轨道底 |
| `--yt-surface-raised` | `#fffdf7` | `#211f1c` | 浮起层:卡片、对话框、下拉 |

层级靠 surface 分层与间距表达,**不用阴影堆叠**。

### 2.2 文字(text)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-text-primary` | `#2e2b26` | `#e8e4dc` | 正文与标题 |
| `--yt-text-secondary` | `#6b6455` | `#a8a296` | 次要说明、辅助信息 |
| `--yt-text-muted` | `#9a9488` | `#7a756b` | 占位、时间戳等从属证据 |

不用比 muted 更浅的文字凑密度;字号与对比度不可为密度牺牲。

### 2.3 边框(border)

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-border-subtle` | `#e6e2d8` | `#35322d` | 默认分隔 |
| `--yt-border-strong` | `#d8d2c4` | `#454138` | 需要强调的分组边界 |

### 2.4 强调(accent)——唯一的彩色

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-accent` | `#4a7fd4` | `#7ba3e0` | 链接、选中、主操作 |
| `--yt-accent-bg` | `#eef3ff` | `#232c3d` | 选中态底 |
| `--yt-accent-border` | `#c7d7ff` | `#3a4d75` | 选中态边 |

### 2.5 语义色(semantic)——只表达状态

| token | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--yt-success` | `#4f9d5d` | `#6fb87d` | 已保存、已完成 |
| `--yt-warning` | `#d8a13a` | `#d8a13a` | 警告、未保存的脏状态 |
| `--yt-warning-text` | `#8a6d3a` | `#d8b96a` | 警告底色上的文字 |
| `--yt-error` | `#b4453a` | `#d06a5e` | 错误、失败动作 |
| `--yt-error-bg` | `#fbe9e7` | `#3a2422` | 错误态底 |

语义色必须搭配非颜色线索(文案、图标、位置),不单独靠颜色传达状态。

## 3. 排版阶梯

字号只有五档,新代码**禁止取阶梯外的值**:

| token | 大小 | 用途 |
|---|---|---|
| `--yt-type-label` | 12px | 徽标、计数、辅助标注 |
| `--yt-type-body` | 13px | 正文、列表、表格、输入 |
| `--yt-type-section` | 14px | 面板内小节标题 |
| `--yt-type-title` | 16px | 窗格标题、对话框标题 |
| `--yt-type-display` | 20px | 页面级唯一主标题(一处界面至多一个) |

- 字重只用 regular / medium / semibold 三档;同级同类元素永远同字号同字重,不因内容长短或数值大小改变。
- 等宽字体(上游 `--ds-font-family-code`)只用于路径、ID、时间戳、代码片段——只设那个标识符本身,不设整句整表。
- 标题用句首大写(中文即自然语句),陈述具体事物;禁止 eyebrow/overline 式的装饰小标、装饰性序号、全大写。
- 段落之间用间距分隔,不用首行缩进;正文行高保持舒适,改写文案而不是缩字号。

## 4. 间距纪律

间距只有六档,新代码**禁止取阶梯外的值**:

| token | 值 | 关系语义 |
|---|---|---|
| `--yt-space-1` | 4px | 最紧:图标与文字、行内元素 |
| `--yt-space-2` | 8px | 组内:标题与其第一段、label 与值 |
| `--yt-space-3` | 12px | 组内:段落与段落、同级列表项 |
| `--yt-space-4` | 16px | 组间:内容组与内容组 |
| `--yt-space-5` | 24px | 大组间:面板内主要分区 |
| `--yt-space-6` | 32px | 章节级:页面上两个实质部分的转场 |

- **每个 gap 只有一个 owner**:由父容器的 gap/stack 设定,子元素不得再加竞争性 margin 参与同一段间距。修一个别扭的间距时,修分组或 owner,不打一次性的 arbitrary margin 补丁。
- 间距表达的是**关系**:关系近则小,关系远则大;不是全界面一把统一 stack。
- 判断整个过渡而不只看 token:大间距挨着欠填充的分区会放大空洞感,该收间距、重排或堆叠。

## 5. 表面与边界

- 页面默认是**一张连续画布**;表面或边界只在表达选择、交互、警告、状态或真实分组时"赚用",分组能用间距表达就不用边框。
- 禁止:卡片套卡片、渐变、发光、玻璃拟态、装饰性阴影、纹理、网格背景、彩色侧栏。圆角克制且一致。
- 感觉"闹"时,减少颜色、字重、边框、表面之间的竞争,**保留一个刻意的锚点**——克制不等于把页面抹成中性均质。感觉"挤"时,删、并、重排内容,而不是缩字号、压间距。
- 不用面板、边框、图标、色块去填证据缺口;内容薄就改善选择与层级,缺口就诚实地空着。

## 6. 阅读型表面构图

proposal 卡片、提炼裁决、邮件分诊结果、实体文档阅读视图等**给人读的论证表面**,额外遵守:

- **双层阅读**:executive 路径(标题、结论、关键值)让忙的读者快速抓住论点;audit 路径(完整记录、来源、限定条件)保留可查证的档案,但不主导第一读。
- **一个焦点关系**:每个阅读时刻有一个主导对象,其余退为支持;同级元素才允许重复成排,非同级重复是模板噪声。
- **标题即论点**:小节标题陈述具体发现或读者问题,不命名文档体裁("概述""详情""其他"是失败标题)。
- **表格是证据**:数字列连同表头右对齐、文字列左对齐;同级单位与精度一致,不伪造精度;表格默认占满所在分区的证据宽度;五个及以上列的表不做窄分栏。
- **结尾落在决定**:页面或卡片收在已解决的决定、含义、下一步或未决问题上;不在一段台账或免责后戛然而止。
- 图标只在显著加快识别时使用;不做装饰图标、图标彩色底砖。不用 stock 图、假截图。

- [ ] 同一层级出现两种字重或字号"将就内容"

- [ ] 给"重要"或"利好"的内容上色
- [ ] eyebrow/overline、装饰性序号、全大写小标
- [ ] 渐变、发光、装饰阴影、玻璃、纹理

## 8. 迁移路径

现状:ui-yantao 全是内联样式 + 硬编码暖纸 hex,light-only,暗色下我们的 pane 不换肤。本文档只定约定,**迁移是独立任务**,不捆绑进行。迁移分三步:

1. **token 落地**:`theme-presenter.ts` 在现有主题写入机制上增发本文档第 2–4 节的 `--yt-*` 一族(浅/暗两组值)。
2. **逐 pane 迁移**:按窗格把内联样式改为引用 token;一次一个 pane,顺带清理阶梯外取值,不做顺手重构。
3. **上门禁**:迁移完成后,给 ui-yantao 加检查(禁裸 hex、禁阶梯外 px),作为迁移的收尾动作。在此之前执行靠 code review 自觉——存量全是违规时上门禁等于立刻红一片。

暗色 token 值在第 1 步落地时以实际渲染效果微调,本文档表格中的暗色值为基准。
